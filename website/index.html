What it is

Not a chat app. Not an editor. An environment.

Most developer tools give you an editor with an AI panel bolted onto the side. Ask it something, and it re-derives context from whatever's visible in the buffer — it doesn't know your architecture, doesn't remember yesterday's decisions, and every session starts from zero.

Grounded, not guessed

Every AI answer is built on a real, incrementally-updated knowledge graph — entities, relations, layers, health scores — computed once and queried, never reconstructed from a raw file dump on every keystroke.

Deterministic first

Questions with one checkable answer — is this actually dead code, did this diff remove a public export — are answered by real parsing and arithmetic. The model explains and drafts; it doesn't invent facts.

Engineering memory that compounds

Decisions, patterns, and learnings persist across sessions and inform future answers, instead of every conversation starting over from a blank context window.

Vision

The environment is the product.

A project opened in AURA gets a persistent, structural understanding of itself before any model is called. Engineering work — multi-step missions, workflow automation, architecture review, governance — runs as first-class, resumable, inspectable processes, not one-shot chat completions. The AI itself is never locked to one vendor.

Engineering Intelligence

Multi-Provider AI

Eleven BYOAK providers behind one shared adapter interface. Adding a provider is a small, self-contained adapter, not a rewrite.

Why AURA Hub

Built for scale, not a demo

01

No vendor lock-in

Eleven AI providers are supported today through one shared adapter interface. Switching providers — or model, mid-conversation — is a first-class, validated operation, never a reconfiguration.

02

A strict, inward-only dependency direction

apps/desktop → @aura/ui → @aura/core — a design system with zero raw hex values, and an architecture explicitly designed to support years of development rather than a demo.

03

Nothing is simulated

Every workflow node, every mission task, every governance score executes for real against the open project. No mocked data paths in the product surface.

04

One pipeline, every feature

Chat, Ctrl+I inline actions, the Workflow Builder, Mission Control, and diagnosis all funnel through the same three entry points — provider validation, error translation, and retry/timeout handling are implemented once and apply everywhere.

npm run dev    # → http://localhost:1420, no Rust needed
