# AURA Hub → Python backend migration — Phase 0 contracts freeze

**Status:** ACTIVE · **Tree revision frozen at:** `141d101` (`feat(backend): add context fabric`)
**Mandate:** reconnaissance + contract publication ONLY. No implementation, no commits from this work.

This directory is the single authority for what a Python backend must reproduce to be
accepted as the AURA Hub backend. Everything here was extracted read-only from the
TypeScript sources and verified against live on-disk state under `~/.aura`
(`AURA_HOME`-overridable). Source citations use `file:line` at revision `141d101`.

## The acceptance bar

> **Wire-compat and format-compat are the acceptance criteria.** A Python route (or
> persisted writer) is done when an existing consumer cannot distinguish it from the
> TypeScript original: same JSON field names, same enum vocabularies, same error
> bodies, same SSE framing, same byte-level file semantics, same security decisions.

The existing verification suites in `scripts/*.mjs` are already black-box
(language-independent) tests. They remain untouched and authoritative throughout the
migration; each phase must keep them green.

## Decision record (user-ratified 2026-08-24)

| # | Decision | Consequence |
| --- | --- | --- |
| D1 | **Diagnosis subsystem is a permanent TypeScript sidecar.** It depends on the `typescript` compiler API (`diagnosis/simulate.ts:9`, `signals.ts:12`, `tsHelpers.ts:8`, `detectors/nullBug.ts:13`, `detectors/brokenApi.ts:10`) — no faithful Python equivalent exists. | Python backend calls diagnosis over HTTP/IPC; its routes (`POST /projects/:id/diagnose`) may proxy to a TS process indefinitely. Never ported, never reimplemented. |
| D2 | **Satellite packages migrate last**, in Phase 12: mission system, governance, knowledge-coding/fullstack, engineering-memory, retrieval, predictive (~13.6k LOC). | Their wire contracts are frozen here, but their *persisted* formats are frozen when their port begins. During strangler cutover they remain TS behind the per-route map. |
| D3 | **Single source of truth at all times.** At most one authoritative implementation per concern; parity proven offline (differential harness), never by double-serving. Strangler = per-route proxy map introduced only at Phase 10. | `~/.aura` files have exactly one writer at any moment. Parked approvals / live runs flip atomically with their state owners or during a quiesced window. |

## Scope boundaries of THIS freeze

Frozen now (Phases 1–10 depend on them):

- Fabric domain types, policy config, approval requests, audit records.
- Workflow definitions, immutable versions, run records (incl. `AgentTrace`).
- Wire conventions, SSE event unions, gates.
- Canonicalization (fingerprints, graph hash) — P0 risk, spec'd to the byte.
- Providers credential-store envelope (shape + crypto parameters; values stay encrypted).
- Automation rule/run envelopes + schedule-state.

Deferred to their phase gate (per D2): mission records, diagnosis records,
intelligence artifacts (`identity/`, `index/`, `engineering-memory/`, …),
conversation/memory internals, satellite-specific files.

## How to verify changes to this directory

1. Every claim carries a source citation; re-check against the cited file before editing.
2. Schemas must validate their sibling goldens (`python3 -c` with `jsonschema`, or any validator) — see "Validation" in `persisted-formats.md`.
3. Parity vectors in `canonicalization-spec.md` were computed with the real TS algorithm; never regenerate them from a reimplementation — recompute only from TypeScript.
4. Nothing here is committed automatically. Review `git status --short` first; this tree carries long-lived user WIP that must never be staged alongside these files.
