# Support

## Getting help

**Have a question about using AURA Hub?** Open a
[question issue](.github/ISSUE_TEMPLATE/question.md) — this is the
primary support channel today.

**Found a bug?** Open a
[bug report](.github/ISSUE_TEMPLATE/bug_report.md) with clear
reproduction steps.

**Want a new feature or change?** Open a
[feature request](.github/ISSUE_TEMPLATE/feature_request.md) explaining
the problem it solves, not just the feature itself.

All issues: <https://github.com/Aura-hub-ai-native-workspace/aura-hub/issues>

## Before opening an issue

1. Search [existing issues](https://github.com/Aura-hub-ai-native-workspace/aura-hub/issues)
   — someone may have already run into it.
2. Check the docs:
   - [`README.md`](README.md) — overview, installation, quick start
   - [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) — how the app is structured
   - [`docs/architecture/`](docs/architecture) — deep dives on each platform
     (Mission Control, Provider Integration, Governance, Predictive
     Engineering, Engineering Memory, Automation Engine)
   - [`CONTRIBUTING.md`](CONTRIBUTING.md) — development workflow
3. For AI provider connection issues, check
   [`docs/architecture/PROVIDER_INTEGRATION.md`](docs/architecture/PROVIDER_INTEGRATION.md)
   first — most connection problems are a missing/invalid API key for
   the provider you're trying to use (AURA is bring-your-own-key; there
   is no built-in default AI).

## Security issues

**Do not open a public issue for a security vulnerability.** See
[`SECURITY.md`](SECURITY.md) for private reporting instructions.

## Response times

AURA Hub is maintained by a small team (see
[`docs/TEAM_GUIDE.md`](docs/TEAM_GUIDE.md)). There's no formal SLA —
issues are triaged as they come in, prioritized by impact.
